# Theming

Colony should be easy to personalize without turning every install into a broken custom UI. Theming should be token-based, previewable, and reversible.

## Goals

- Let each user make the app feel comfortable.
- Let workspace admins define a default brand.
- Support light, dark, and high-contrast appearances.
- Support density choices for compact and relaxed workflows.
- Allow navigation and button placement preferences.
- Keep the interface accessible.
- Avoid arbitrary CSS or unbounded layout changes in the first version.

## Theme Levels

### System Theme

The built-in default theme. This should be polished enough that most users never need to change it.

### Workspace Theme

An admin-configured default:

- Accent color.
- App icon or workspace mark later.
- Light/dark preference.
- Sidebar style.
- Density default.

### User Theme

A user override:

- Accent color.
- Message layout.
- Sidebar width.
- Compact or comfortable density.
- Button placement preference.
- Reduce motion.
- High contrast.

## Design Tokens

Use named tokens instead of raw colors throughout the UI:

- `color.background`
- `color.surface`
- `color.sidebar`
- `color.text.primary`
- `color.text.secondary`
- `color.accent`
- `color.border`
- `color.danger`
- `color.warning`
- `color.success`
- `radius.control`
- `radius.card`
- `spacing.compact`
- `spacing.comfortable`
- `font.body`
- `font.monospace`

Native clients should map these tokens into platform-native color and typography systems.

## Button Customization

Button customization should focus on placement and behavior before visual styling.

Examples:

- Place compose button in toolbar or lower corner.
- Show icon-only toolbar buttons or icon plus label.
- Prefer compact message action buttons.
- Keep primary actions on the trailing side or leading side.

Do not allow arbitrary per-button color overrides in the first version. That creates accessibility and support problems.

## Accessibility Rules

- Maintain contrast ratios for text and controls.
- Respect reduced motion.
- Respect dynamic type on Apple platforms.
- Never rely on color alone for status.
- Keep keyboard navigation and focus states visible.

## Storage

Themes should be stored as structured JSON-like records:

- Workspace default theme.
- User preference override.
- Resolved theme generated by merging system, workspace, and user preferences.

Clients should cache the resolved theme and update live when it changes.

## MVP Theme Features

- Light/dark/system mode.
- Accent color.
- Compact/comfortable density.
- Sidebar expanded/collapsed default.
- Message layout: cozy or compact.
- Reduce motion.
